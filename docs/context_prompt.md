# Prompt de continuidad

Trabaja sobre la versión 1.7.0 del Sistema de Expediente Clínico. Conserva la compatibilidad de datos y las rutas existentes. Usa `app/db.py` para persistencia/respaldos/migraciones verificables, `app/core/validators.py` para toda entrada y `AuditLog.record()` para eventos críticos. Mantén los roles `admin`, `medico`, `recepcion`, separados de los perfiles `medico_general`, `dentista`, `nutricion`; recepción nunca accede a contenido clínico.

Sólo Nutrición puede capturar o importar antropometría. La nota clínica y la receta ordinaria son documentos distintos. Sólo Medicina/Odontología con cédula y domicilio completos puede emitir una receta. Los folios emitidos son inmutables: las correcciones crean sustituciones trazables y los documentos adicionales conservan folio independiente. No se admiten medicamentos sujetos a receta especial y toda impresión requiere revisión/firma autógrafa. Los cambios de contraseña invalidan sesiones y ninguna credencial llega a logs o auditoría.

El shell 1.7.0 contiene sidebar por áreas, búsqueda global de pacientes, sede local informativa, notificaciones con estado vacío, breadcrumb y tema claro/oscuro persistente. La identidad completa vive únicamente en el footer del sidebar. El topbar compacto permanece visible porque el contenido principal es el único contenedor vertical desplazable. No crees rutas ni datos para módulos planificados: Laboratorio, Hospitalización, Facturación, Inventario, Reportes, Configuración y Portal del paciente deben permanecer como estados visuales deshabilitados. Recetas abre el listado existente en contexto de recetas; Plantillas, Usuarios, Auditoría y Configuración se agrupan bajo Administración.

El Dashboard presenta tres KPI reales y accionables —pacientes registrados, citas del día y consultas pendientes—, omite ingresos y mantiene Acompañamiento Intermedio junto a Próximas citas. No vuelvas a crear una fila separada de Acciones rápidas: cada KPI contiene un enlace informativo y una acción independiente, respetando permisos. **Pendientes de atención** es la única vista para pendientes de agenda e historial; **Sin consulta reciente** aparece únicamente para Nutrición. Recetas y Expedientes permanecen en el sidebar. La gráfica, tareas y actividad deben salir de SQLite. El modal de citas inicia cerrado; las pestañas clínicas, el shell y las vistas de impresión deben funcionar mediante controles locales y respetar la paleta oscura. En el detalle, ordena Historial Médico, Alimentación y Actividad Física. No incluyas bases, secretos, logs, respaldos, cachés o entornos virtuales en la entrega.

Agendar cita desde el KPI abre exclusivamente `/pacientes/agendar-cita`: selector buscable de pacientes activos, calendario de 21 días, fecha adicional y horarios con estado explícito. No agregues ese acceso al sidebar ni retires el modal del detalle. El flujo rápido sólo crea; si ya existe una cita programada debe enviar al detalle para reagendar. La disponibilidad del navegador nunca sustituye la validación final del servidor.
