# Prompt de continuidad

Trabaja sobre la versión 1.6.6 del Sistema de Expediente Clínico. Conserva la compatibilidad de datos y las rutas existentes. Usa `app/db.py` para persistencia/respaldos/migraciones verificables, `app/core/validators.py` para toda entrada y `AuditLog.record()` para eventos críticos. Mantén los roles `admin`, `medico`, `recepcion`, separados de los perfiles `medico_general`, `dentista`, `nutricion`; recepción nunca accede a contenido clínico.

Sólo Nutrición puede capturar o importar antropometría. La nota clínica y la receta ordinaria son documentos distintos. Sólo Medicina/Odontología con cédula y domicilio completos puede emitir una receta. Los folios emitidos son inmutables: las correcciones crean sustituciones trazables y los documentos adicionales conservan folio independiente. No se admiten medicamentos sujetos a receta especial y toda impresión requiere revisión/firma autógrafa. Los cambios de contraseña invalidan sesiones y ninguna credencial llega a logs o auditoría.

El shell 1.6.6 contiene sidebar por áreas, búsqueda global de pacientes, sede local informativa, notificaciones con estado vacío, breadcrumb y tema claro/oscuro persistente. La identidad completa vive únicamente en el footer del sidebar: avatar, nombre, rol/perfil y botón `...` que despliega cédula condicional, cambio de contraseña y cierre de sesión. El topbar no debe volver a mostrar identidad. No crees rutas ni datos para módulos planificados: Laboratorio, Hospitalización, Facturación, Inventario, Reportes, Configuración y Portal del paciente deben permanecer como estados visuales deshabilitados. Recetas abre el listado existente en contexto de recetas; Plantillas, Usuarios, Auditoría y Configuración se agrupan bajo Administración.

El Dashboard presenta tres KPIs reales —pacientes registrados, citas del día y consultas pendientes—, omite ingresos y mantiene Acompañamiento Intermedio junto a Próximas citas. **Pendientes de atención** es la única vista para pendientes de agenda, consulta e historial; no vuelvas a crear un bloque paralelo de alertas con las mismas fuentes. Acciones rápidas sólo contiene Nuevo paciente, Agendar cita y Nueva consulta; Recetas y Expedientes permanecen en el sidebar. La gráfica, tareas y actividad deben salir de SQLite y respetar permisos. El modal de citas inicia cerrado; las pestañas clínicas, el shell y las vistas de impresión deben funcionar mediante controles locales. No incluyas bases, secretos, logs, respaldos, cachés o entornos virtuales en la entrega.
